# NOOR — Climate Intelligence & Resilience

**See the risk. Save lives.**

NOOR helps communities and decision-makers understand heat risk, find the people most
exposed, plan cooling, water and medical resources, and prepare for extreme heat. It
follows one workflow:

**Climate data → Risk analysis → Vulnerability assessment → Early warnings → Resource planning → Scenario comparison**

Every method is plain Python you can read and change. No machine learning, no hidden
models, no paid services.

> **Demonstration data.** The district “Saptapur”, its 16 wards and every population,
> vulnerability, resource and weather figure in the bundled database are **synthetic**
> (generated by `noor/seed.py` with a fixed random seed). The app says so on every page.
> NOOR is a decision-support tool and does not replace warnings from the India
> Meteorological Department (IMD), State Disaster Management Authorities or local officials.

## Run it locally

Requires Python 3.12 or newer.

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows   (macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt   # numpy, pandas, matplotlib, seaborn
python run.py                     # http://127.0.0.1:3060
```

The first start creates `instance/noor.db` and fills it with the demo data. `python run.py --reset`
deletes the database and rebuilds it; `python run.py --port 3061` uses another port.

Run the tests (Python's built-in `unittest`, 150 tests):

```bash
python -m unittest discover -s tests
```

## What is in it

| Page | What it does |
| --- | --- |
| Overview `/` | Mission, workflow and live headline numbers |
| Dashboard `/dashboard` | Risk map, scores, hotspots with reasons, alerts, regional summary, temperature heatmap, readiness, data freshness |
| Data explorer `/explorer` | Daily Tmax/Tmin/humidity/heat index per ward and date range, missing days marked, monthly means, ward comparison, CSV export |
| Risk `/risk`, `/risk/<code>` | Four separate dimension scores, combined score, category, confidence; filters, sorting, what-if weights; step-by-step explanation per ward |
| Vulnerability map `/map` | Schematic ward grid (Seaborn heatmap) by score, hazard, exposure, vulnerability or capacity |
| Alerts `/alerts` | Rule engine, severity, trigger vs threshold, period, actions, confidence; acknowledge/resolve; local notification preview (nothing is sent) |
| Resources `/resources` | Inventory of five resource types; add, update status/amount, delete |
| Planning `/plans` | Greedy allocation (risk-first or population-first), unmet demand, utilisation, strategy comparison, saved plans |
| Scenario lab `/scenarios` | +°C, longer heatwave, new cooling centres, water/medical capacity, budget and staff limits; before/after |
| Reports `/reports` | CSV reports with provenance headers; SQL query viewer (JOIN / GROUP BY / HAVING) |
| Data & sources `/data` | Provenance of every source, CSV import with row-level validation, add a location |
| Method `/methodology` | The method, generated from `noor/settings.py` so it always matches the code |
| JSON API `/api/...` | See [docs/API.md](docs/API.md) |

## Project layout

```
run.py                 start the local server
api/index.py           Vercel entry point (class handler)
noor/
  settings.py          every weight, bound and threshold
  models.py            Location, Region, Resource (+5 subclasses)
  database.py          sqlite3 access, threading.Lock for writes
  schema.sql           8 tables
  queries.py           readable SQL examples
  seed.py              synthetic demo data (NumPy, fixed seed)
  climate.py           heat index, hazard indicators, explorer tables (NumPy/Pandas)
  risk.py              RiskEngine (min-max normalisation + weighted sum)
  alerts.py            AlertRule classes + WarningEngine
  allocation.py        AllocationPlanner (greedy loop)
  scenario.py          Scenario Lab
  importer.py          CSV validation (Pandas)
  charts.py            Matplotlib/Seaborn PNG charts
  reports.py           CSV reports with provenance
  service.py           NoorService: connects database and calculations
  web/server.py        http.server request handler and routing
  web/pages.py         HTML pages
  web/api.py           JSON endpoints
  static/              style.css, favicon.svg
scripts/fetch_open_meteo.py   optional: download model-derived weather as an import CSV
tests/                 unittest suite
docs/                  documentation
```

## Limitations (short version)

- All bundled data is synthetic; no live feed is connected. Real data can be imported as CSV
  (for example model-derived weather from Open-Meteo via `scripts/fetch_open_meteo.py`).
- Thresholds, weights and planning rates are NOOR defaults, not official criteria, and have
  not been validated against health outcomes. Scores are relative priorities, not predictions.
- The map is a schematic grid, not real geography.
- The hosted demo keeps its database in temporary storage: changes there are not permanent.
- There is no login. Anyone who can reach the server can change data; add authentication
  before using it with real data on a shared network.
